# פתיחת טיול חדש

- לעבוד משורש VacationAgent ולקרוא knowledge/traveler-profile.md ואת אינדקס knowledge/lessons/AGENTS.md. לטעון רק לקחים רלוונטיים ליעד/סגנון.
- לברר יעד, מזהה, תאריכים אם ידועים, אזור זמן, נוסעים ואילוצים מהותיים חסרים. מידע שכבר קיים במקורות מחוברים יש לקרוא לפני ששואלים שוב; יומן כפוף ל־agent/policies/calendar-policy.md.
- מזהה תיקייה: lowercase-kebab-case; שם הטיול יכול להיות בעברית. לא להחליף פרויקט קיים.
- להריץ `npm run trip:new -- --trip <id> --name <name> --timezone <IANA> [--start YYYY-MM-DD --end YYYY-MM-DD]`. הפקודה יוצרת manifest, מסד נפרד, תוכנית ריקה, מסמך עברי, תחקיר ותיקיות עם AGENTS.md. אין לזרוע ממסלול קודם.
- להוסיף brief קצר מתוך אילוצים ידועים ושאלות פתוחות. לשמור הפניות לטיסות/הזמנות קיימות, לא קישורי הזמנה פרטיים במסמכים כלליים. להוסיף מזהי טיסות מוגנות ל־trip.json.
- להשאיר planningStage=draft עד שיש תוכנית מעשית. אין להמציא פעילויות כדי למלא ימים או לסמן נתונים חסרים כאילו אומתו.
- תכנון ראשוני משתמש ביום צפוף ומחושב: יותר יעדים סמוכים וזמן ביקור מותאם; נסיעות, אוכל, תורים ושעות פתיחה נשארים מציאותיים. לבדוק עודף זמן ולתכנן הרחבות אזוריות כשמתאים.
- להריץ `npm run validate -- --trip <id>`, לוודא שהמסד שייך רק לטיול החדש, ולציין אילו פרטים נשארו פתוחים. בחירת טיול פעיל מתבצעת ב־agent/config/travel-agent.yaml לפי בקשת המשתמש.
- יצירה ותכנון מקומי אינם אישור להזמנה, כתיבה ליומן, פרסום Drive או הודעה לספק.
